# 境界のオルケストラ

`chat.md` の最後の設計をもとにした、リアルタイムATB戦闘デモです。3人のパーティーで一戦し、武器を拾って編成を変え、次の一戦へ進みます。

## 起動

Node.js 22.12以上とnpmを使用します。

```sh
npm ci
npm run dev
```

表示されたローカルURL（通常は `http://127.0.0.1:5173`）を開き、「戦闘開始」を押してください。選択中の仲間は手動で指示し、それ以外の仲間は装備中の武器で自動行動します。サーバーやAPIキーは不要です。フォントはGoogle Fontsを利用し、通信できない場合はシステムフォントに切り替わります。

## 操作

戦場は3人分の縦幅を確保し、同列の人数や画面の高さによって駒を縮小しません。初期表示はキャラの「周囲に展開」。周囲では技を選び、ATB・行動予約欄の「行動開始」で確定します。画面上の「メニュー位置」から「足元にまとめる」「下の操作盤」にも切り替えられます。[比較の狙いと検証条件](docs/near-command-menu-study.md)。

**攻撃対象と支援対象を保持し、技を一押しで下書きへ追加 → 行動開始で一組を放つ。** コマンド・補助・予約を常設し、補助やログを表示したまま技の追加と予約の取消ができます。どちらの対象を選び直している最中でも、技は対応する側の相手へ入ります。移動・武器変更・オプティマは下書きを使わない直接指示です。[現在の常設操作盤](docs/persistent-command-desk.md)、[二重対象と戦闘ルール](docs/dual-target-controls.md)。

| キー                           | 操作                                                         |
| ------------------------------ | ------------------------------------------------------------ |
| `Z`                            | 操作先にかかわらず基本技を下書きへ追加                       |
| `Enter`                        | 対象選択中は基本技、補助・予約では選択項目を決定             |
| `X` / `C`                      | 主力技 / 自分への防御を下書きへ追加                          |
| `H`                            | 見えている下書きだけを一組として実行確定                     |
| `B`                            | 確定済みの未開始分を取消。下書きは残す                       |
| `Esc` / `Backspace` / `Delete` | 対象操作へ戻す互換操作。下書き・確定列は変えない             |
| 矢印キー                       | 対象は駒の位置に沿って移動。補助は左右で表示・上下で項目選択 |
| `,` / `.`                      | 味方 / 敵のどちらを選び直すか切替                            |
| `J` / `K` / `R`                | 後列へ / 前列へ / 前後を切り替えて移動開始                   |
| `W`                            | もう一方の武器へ変更を指示                                   |
| `U`                            | 4つのオプティマを順に切替                                    |
| `I` / `T`                      | 操作先を対象 → 補助 → 予約 → 対象の順に切替                  |
| `V` / `L`                      | 保持中の支援対象へ救急薬を追加 / 戦闘ログを表示              |
| `1` `2` `3` / `Q` `E`          | 1 ATBのキャラ交代を先頭に予約                                |
| `A` `S` `D` `G` / `7` `8` `9`  | 特定のオプティマ / 一括隊列を直接指定                        |
| `Space`                        | スローと通常速度を切替                                       |
| `P`                            | 休憩ポーズの開始・解除                                       |

Tabでボタンや操作ヘルプへ移動した場合、そのボタンのEnter・Spaceは通常の決定として動きます。フォーカス移動だけでは技を追加しません。補助の「補助・オプティマ・隊列・ログ」は直接選べるため、戻る操作を挟まず次の操作へ移れます。ログには「古い記録・新しい記録・最新」のボタンがあり、ログ本文にフォーカスを置いた矢印やPageUp/Downは本文のスクロールに使えます。休憩・操作説明などのダイアログには閉じる操作とEscを残します。戦術停止と`F`の割当は廃止しました。補助やログの表示中も戦闘時間が進み、休憩は画面を覆って止めます。

移動は入力時に開始し、既定0.85戦闘秒で所属列が変わります。実行中の技・硬直やATB不足を待たず、下書き・実行中の技・支払い済みATBを変更しません。武器変更は下書きを使わず、実行中の技と硬直が終わった安全な区切りから既定0.65戦闘秒で切り替えます。変更後に使えなくなる依存技は解除されます。オプティマは全経路で3人の武器枠だけを切り替え、隊列を伴いません。

技の下書きはATBが満タンでも自動実行しません。行動開始で確定した一組の合計コストが貯まり、現在の一手が終わると開始します。実行中に次の下書きを作れますが、未開始の確定列は一組まで。確定済みの未実行分と下書きを合わせて最大ATBと同じコスト・手数上限を使い、0 ATBの薬も1手に数えます。直接の移動・武器変更はこの枠を使いません。

後続取消は現在の一手・最後の硬直・ATB・下書きを残します。一件取消は予約欄の下書き・未実行行を押すか、「予約を選ぶ」から行います。表示中の補助やログはそのままです。一件取消後は同じボタンが「取消済み」として残り、フォーカスを保ちます。Tab・方向入力・別の行の選択まで、決定の連打で次の予約を消しません。[下書きと確定列の導入記録](docs/sequence-palette.md)。

### 対象の印

足元の**丸環は支援対象、角形の照準は攻撃対象**です。頭上の印は操作キャラ、外側の四隅は選び直している対象を示します。両対象はパーティーで共有し、キャラ・武器・オプティマを替えても保持します。自分への防御だけは操作キャラへ入ります。

技ボタンには技アイコンを表示し、コマンド側と予約欄には対象の小肖像を置きません。宛先は戦場の印、ボタンのtitleと読み上げ名で確認できます。列技は追加時に選択個体がいる列を保存します。その後に対象を選び直しても追加済みの個体ID・列は変わりません。仲間AIはこの選択から独立して、[ロールと戦況から対象を選びます](docs/targeting.md)。

対象が不在になると、同じ陣営の生存者へ自動で切り替えます。下書き・確定予約・未着弾の行動も継続し、再押下による確認は不要です。列技は対象列が空になった場合に生存者がいる列へ切り替えます。対象の変更だけでは技を追加しません。技の追加成功は技アイコンが下書きへ収まる動きと、そこに残る技で確認できます。印の説明は任意の「？」ヘルプに置き、読み上げ用の技名・宛先・結果も保持します。

View / Share / −で対象・補助・予約の操作先を順に選びます。コマンド、補助の表示、予約欄は消えません。補助内は左右で「補助・オプティマ・隊列・ログ」、上下で項目・履歴を選びます。基本技の顔ボタンは対象操作中に基本技を追加し、補助・予約の操作中は項目を決定します。主力技・防御・実行トリガーはどの操作先でも使えます。実行トリガーは既存の下書きだけを確定し、補助で選択中の薬などを勝手に追加しません。

「十字キーで選択」プリセットでは四方向を項目選択へ使い、移動・武器・オプティマ・対象側切替を補助メニューから選べます。アナログ入力や同時押しなしで到達可能です。選択移動だけがリピートし、技・直接変更・開始・取消・スローは一押し一回です。

対象・武器・操作キャラ・列・操作先の変更と技／行動開始が同じ入力ポーリングに入ると、変更を先に反映し、その技／開始は受け付けず再押下を示します。Viewと決定の同時押しで、直前の予約を取り消すことも防ぎます。右スティックによる編集側だけの切替は宛先を変えないため、技と併用できます。設定は`orchestra-gamepad-v7`へ保存し、旧版の物理番号・軸・反転を保ちながら役割を移行します。切断時は休憩へ入り、再接続後は手動で再開します。

Chromeの仮想パッドで3系統と十字キー選択を検証します。現行配置の物理ゲームパッドでの操作感、実際の読み上げソフト、誤操作率は未検証です。

### 戦場のエフェクト

技の解決時には実際の対象へ斬撃・射撃・魔法・打撃・回復・防護・移動・ブレイクなどを表示します。数値はコアの実値を使います。演出は戦闘時間に合わせて進み、スローで遅くなり、休憩で止まります。

下書き追加のアイコン移動は入力結果専用で、戦場の命中・回復演出とは分けます。OSの「動きを減らす」では飛翔・拡大・回転を抑え、対象の印と下書きの宛先は静止状態で残します。戦闘結果・AI・リプレイの処理は描画から独立しています。

## AI鑑賞

フレームを飛ばさず動画へ書き出すには `npm run record:ai -- --out artifacts/recordings/ai-watch`。標準の2連戦を60fps・効果音付きMP4として保存します。[録画方式と再現・検証](docs/ai-recording.md)。

右上の「AI鑑賞」を押し、方針・予約方式・再生速度を選んで「AI鑑賞を開始」。6つの既存AIをWebで動かし、戦場のエフェクト、3人のHP・ATB・予約、判断理由を見られます。

- 方針：既存6方針に、編成適応／攻勢特化を追加。既定は編成適応。装備方針も独立に選べます。
- 予約方式：従来AI・1手／予約AI・1手／予約AI・3手。既定は予告対応・3手。
- 再生速度：1・2・4倍。「鑑賞を一時停止」で画面を見たまま停止・再開でき、Spaceでも操作できます。
- 第一戦後は戦利品を装備し、自動で第二戦へ進みます。
- 戦闘中にもAIへ操作を渡せます。「手動に戻る」でAIの未実行予約を取り消し、通常速度で操作を引き継ぎます。実行中の技は続行します。

鑑賞の速度変更は戦闘ルールの倍率とは別です。4倍速でも同じ観測間隔・反応時間・ATB規則で進み、リプレイ用の入力を記録します。詳しくは[現在の操作とAI鑑賞](docs/live-controls.md)を参照。

## 戦闘ログと戦闘セット

画面下の「戦闘ログ」を開くと、全イベントを戦闘別・種類別に絞り込んだり、名前・技名で検索したりできます。「最新を追う」を外すと以前の場面を読めます。JSON保存は絞り込み前の全ログを書き出します。戦利品・結果画面からも確認でき、状態保存／復元はログも保持します。ログの時刻は2戦を通した累計戦闘時間です。

開始前には5つの戦闘セットを直接選べます。基本の「鐘楼の関門」に加え、「双盾の城門」「交差砲火」「追撃の猟兵」「灰雨の消耗戦」を用意しました。各2連戦、強度1〜10で、敵HPは段階ごとに1.30倍、ダメージは1.40倍になります。戦利品や味方の初期条件は共通です。

## 採用したルール

既存のAI観測・攻略限界・予約方式の比較資料は、防御0 ATB・全員自動行動の `orchestra-1` 時点の記録です。旧版の速度調整前後を各10,000ランで測定した結果は[戦闘テンポとシナリオ傾向](docs/tempo-study.md)にまとめています。

- 武器 → アーキタイプ → 固定ロール。AはHP削りとチェイン維持、Bはチェイン上昇、Dは被害を受け止める防護、Sは回復・強化・弱体。今回Dに移したのは守護騎士だけで、技や数値は変更しない。通常の防御・移動は全員が利用でき、Dと前列は独立。武器にない技は手動でも使用不可。
- 一人2本、4オプティマ。武器個体の重複装備は不可。オプティマは武器そのものではなく装備枠を参照。
- すべてのオプティマ操作で武器構成と隊列は独立。全員前列・全員後列も可能。移動・職変更によるATB補充や即応ボーナスはなし。
- 全職の前列はHPダメージ・チェイン上昇が各1.25倍。後列は近接威力0.85倍、魔法・射撃は1倍。攻撃側の倍率は技の開始時に確定し、編成ボーナスとは乗算する。味方後列の被ダメージは0.72倍。[前列の仕様と検証](docs/front-row.md)。
- チェインは敵個体に保持。100%開始、200%で12秒間ブレイク。ダメージ倍率はチェイン値に比例し、ブレイク中も500%まで上昇。Aは減衰猶予を延ばし、Bは大きく伸ばす。
- 防御は1 ATBを実行開始時に消費し、0.4秒の準備後、6秒間自分の被ダメージを半減する。発動後の硬直は1秒。ATB不足でも予約でき、充填まで待つ。
- 選択中の仲間は予約が空なら指示待ち。実行中の技・確定した技・移動・武器変更は続行し、ATBは現在の充填規則に従う。選択を外すと自動行動へ戻る。AI鑑賞では全員が自動行動する。
- 技は発動までの準備と発動後の硬直を持つ。基本攻撃は合計1.9〜2.2秒、列攻撃は3〜3.2秒。効果は準備終了時に一度だけ発生し、硬直中は次の技・武器変更を待つ。直接の列移動は並行して開始する。予約の追加・取消は硬直中も可能。技ボタンの説明と仲間の状態から発動・硬直を確認できる。
- ATBは4区画、既定は毎秒0.85（ボーナスなしの待機時、0から満タンまで約4.7秒）。基本攻撃のオートは2区画まで貯めて1区画技を使うため、1区画からの手動介入に余地がある。支援は1区画から必要時に実行し、不要な回復・防護を避ける。
- 手動予約は各人最大ATBまでの合計コスト、手数も最大ATBと同じ上限。手動技を追加順に実行し、取消後も残りの順序を保つ。直接の移動・武器変更は手数に含めない。ATBと薬は実行開始時に消費。薬は全員の予約で残数を超えない。対象が不在になった技は生存者へ切り替えて継続し、武器変更の取消や一括切替で使えなくなった技は解除してログへ残す。
- 手動の直接移動と一括隊列は現在の技と並行して進み、武器・オプティマ変更は現在の技の終了を待つ。AI等の計画に含まれた移動・武器のステップは、そのステップに到達してから開始する。
- 移動は0.85秒、職変更は0.65秒。所属列は移動完了時に変化。列攻撃の対象は着弾時に判定。個体追尾は列移動でも回避できない。
- 引き寄せ・押し出しは手動技。移動可能な構えだけを中断し、移動後は3秒間「踏ん張り」。重装衛兵はブレイク中だけ移動可能。前列の衛兵は敵後列へのダメージを40%軽減する。
- 敵剣兵の押し出し後に自動復帰しない。旗手の緊急退避は0.45秒で味方列を移動させ、途中の技を中断する。消費済みATBは返さない。使用者自身が退避しても、1.15秒の硬直を経て次の行動へ進む。
- 敵の予告は3.2〜4.8秒。各戦闘セットの従来予告を1.6倍、初動・攻撃後の待ちを1.5倍に延長。ブレイクは12秒、防御6秒、防護9秒にし、チェイン減衰猶予も延ばす。
- 集中力100、自然回復なし。スロー開始に4、スロー（0.25倍）中は実時間毎秒4を消費。枯渇すると通常速度へ戻る。戦術停止は廃止し、休憩ポーズを残す。
- メニューだけでは時計は止まらない。別タブへ移ると休憩ポーズに入り、戻ってから手動再開する。不在時間はまとめて進めない。
- 第一戦後に3本の固定報酬を獲得して全員回復。装備・プリセットを変えて第二戦へ。全滅で敗北。勝利・敗北のどちらでも再試行可能。

数値は試作用です。武器・技の定義は [`src/content/data.ts`](src/content/data.ts)、敵編成・攻撃パターン・強度倍率は [`src/content/encounters.ts`](src/content/encounters.ts)、戦闘の解決規則は [`src/sim/engine.ts`](src/sim/engine.ts) にあります。

## 実験室

右上の「実験室」で次の操作ができます。

- seed、遭遇、ATB速度、移動／職変更時間、敵の攻撃倍率、集中力消費を変えて再開始。
- 「分離＋一括隊列」「分離＋個別隊列のみ」を切り替えて比較。旧`linked`設定を認識する場合も現在のオプティマは武器だけを変更し、隊列は独立します。
- 出発前の武器・プリセット・隊列編集。「検証用に全武器を追加」でドロップ待ちを省略。
- 出発前には画面下のオプティマと隊列ボタンで初期構成を選択。「同じ条件でリトライ」は装備・初期隊列も維持して現在の遭遇をやり直す。
- 現在状態を一時保存し、その時点へ戻る。状態JSONには時計・ATB・HP・予約・準備中の技・移動・乱数状態・装備・設定を含む。
- リプレイJSONを保存／読み込み。実時間tickと入力順を記録し、同じtickに入れた複数の指示も再現する。読み込みでは待ち時間なしで終端まで再生し、その状態から再操作できる。
- 戦闘時間、実時間、与被ダメージ、回復、集中力、ブレイク、コア指示数と入力・イベントログを表示。総合点や「正しい行動」への採点はしない。

画面の一時保存はメモリ上だけです。ページを閉じる前に残したい場合はJSONを書き出してください。現行ルールは `orchestra-16`。交代は1 ATB・発動0.3秒で、交代前後のキャラの予約を保持します。常設操作盤の変更では戦闘計算を変えておらず、ルール版を据え置きます。旧版の途中状態・リプレイは直接再開できません。過去の印は閲覧と遭遇開始からの比較用に残します。リプレイは同一ルールバージョンのみ読み込み可能で、外部JSONは形式と値を検証します。形式上の上限は5MB、30,000入力、216,000tick（実時間1時間）です。

## 構成と検証

```text
src/sim/       UI非依存の型・コマンド・固定刻み更新
src/content/   武器・技・初期編成・調整数値
src/client/    React、入力、CSSとSVGの戦場表示
src/input/     パッドの機種別割当・入力判定・戦闘選択状態・画面内ナビゲーション
src/lab/       記録、状態保存、リプレイ、JSON検証
src/ai/        複数AI、観測情報の制限、比較実行とログ集計
scripts/       ヘッドレス戦闘と入力比較
tests/         ルール・統合テストとPlaywright E2E
```

戦闘コアは`command(state, input)`と`step(state)`で明示的に渡された状態だけを更新します。1tickは実時間1/60秒、戦闘時間は時間操作倍率を掛けて進みます。衝突判定をCSSアニメーションやReactのライフサイクルに依存させていません。同一tickでは味方ID順、その後に敵ID順で解決します。

```sh
npm test
npm run build
npm run test:e2e
npm run sim
npm run sim -- --seed 42 --out /tmp/orchestra-replay.json
npm run sim -- --replay /tmp/orchestra-replay.json
npm run sim -- --replay /tmp/orchestra-replay.json --atb 1.2 --enemy-power 1.1
```

E2Eはインストール済みのGoogle Chromeを、テスト専用の一時プロファイルで利用します。Chromeがない環境では`playwright.config.ts`の`channel: 'chrome'`を外し、`npx playwright install chromium`でテスト用ブラウザを用意してください。

ヘッドレスの既定方針は`balanced`です。勝利は操作性や戦術の優劣を証明しません。`--replay`と併用する`--atb`などはルールを変える実験で、完全再現とは区別して出力します。UIの一操作が複数のコア指示を発行する場合があるため、「コア指示数」はクリック数ではありません。

## 複数AIを比較する

| `--policy`  | 戦い方                                                |
| ----------- | ----------------------------------------------------- |
| `autopilot` | 初期ABSで自動行動に任せる                             |
| `rush`      | 全員前列、ABBで崩してAABで仕留める                    |
| `balanced`  | HP72%未満で回復構成へ戻す                             |
| `rear`      | 全員後列のABSを維持する                               |
| `tactician` | 引き寄せ、列攻撃、予告への退避・防御、負傷時の回復    |
| `focus`     | `tactician`と同じ方針に、予告を考える間のスローを追加 |

```sh
# 単独実行。判断理由と全イベント、リプレイを保存
npm run sim -- --policy tactician --seed 1307 --dir artifacts/ai-run

# 6種類 × 30 seed × 攻撃倍率3段階 = 540ラン
npm run sim -- --compare --seeds 30 --seed 1307 --powers 1,2,3 --dir artifacts/ai-comparison

# 引き寄せ／列攻撃／退避・防御の切除比較と、反応時間の比較
npm run sim -- --study --seeds 30 --seed 1307 --dir artifacts/ai-study

# 条件を指定して一例を調べる
npm run sim -- --policy tactician --ablation no-row --enemy-power 3
npm run sim -- --policy focus --reaction 1.25 --interval 0.25
```

AIが使うのは通常の戦闘コマンドです。未来の行動タイマーや乱数状態は観測できず、直接HPやATBを変更しません。装備更新は全AI共通で、武器を選ぶAIは今回の比較に含めません。

予告対応と時間操作併用のAIには、既定0.35実秒の人工的な反応待ちがあります。観測間隔0.25実秒ごとに判断するため、実際には0.5秒後の観測で指示します。`--reaction 0`では待ち時間がなくなり、スローも使いません。この遅延は人間の実測値ではありません。

各ランの入力を再生して最終状態の完全一致を検証します。比較フォルダーの`results.json`に全結果と実装のSHA-256、`report.md`に表、`traces/`に各条件の先頭seedの全イベント・判断理由・リプレイ・状態サンプルが入ります。戦闘コアの直近160件とは別に、UIとヘッドレス実行の両方で全イベントを収集します。生成物は`artifacts/`に置き、Gitの対象から除外しています。

実行結果を読んだ考察は [docs/ai-observations.md](docs/ai-observations.md) にあります。

## 現行AIの攻略限界を探る

速度調整前後の比較は[戦闘テンポとシナリオ傾向](docs/tempo-study.md)。全5セット・6方針と予約方式を一括で測定できます。

```sh
npm run sim:scenarios -- --dir artifacts/scenario-repeat
```

```sh
# 4セット × 10強度 × 6 AI × 20 seed = 4,800ラン
npm run sim:limits -- --seeds 20 --seed 1307 --dir artifacts/ai-limits

# 特定の戦闘を同じ条件で観測
npm run sim -- --policy focus --set bulwark --level 7 --seed 1307 --dir artifacts/bulwark-l7
```

`sim:limits` は判断・観測コードをSHA-256で固定し、各条件の勝利・敗北・時間切れそれぞれの代表リプレイと全ログを保存します。`--sets pursuit,attrition --levels 4,5,6` で測定範囲を絞れます。勝率90%以上の最高強度を出しますが、測定範囲での結果です。失敗ランの平均時間をクリア速度へ混ぜません。

**[4,800ランの結果と負け方の考察](docs/ai-limits.md)**、[再現条件・ソースハッシュ・全強度集計](docs/ai-limits-results.json)を保存しています。

## 予約を使うAIの比較

```sh
# 従来 / 行動中の次の1手 / 最大3手の積み込みを同条件で比較（4,800ラン）
npm run sim:queue -- --seeds 20 --seed 1307 --dir artifacts/queue-study

# 3手予約の戦闘を単独で観測
npm run sim -- --policy tactician --planning queue --set crossfire --level 6 --seed 1307 --dir artifacts/queue-example
```

`--planning legacy` が既定で、従来のAIを維持します。`next` と `queue` は同じ新しい判断ロジックで、予約上限だけが1手／3手です。AIは確定予約用の追加・取消コマンドを使い、緊急時は攻撃予約を取消してから防御や薬を積みます。手動の下書きとは別に扱います。**[操作仕様・比較結果と観測した戦闘](docs/queue-controls.md)**、[全強度の集計・実装ハッシュ](docs/queue-study-results.json)を保存しています。

## デモの範囲

5セット各2遭遇・9武器・7アーキタイプで戦闘と武器更新の一巡を試すためのものです。ランダムマップ、素材強化・分解、永続解禁、大量のランダム特性、振動、標的の列を途中まで追う攻撃は含めていません。初期案にあった6ロール、前列必須、無料のメニュー停止、即応成功のATB報酬も、会話後半の変更に合わせて採用していません。

[操作ごとの効果音](docs/audio-feedback.md)を実装済み。上部でミュート、実験室で音量を調整できます。[編成ボーナスの12,000戦比較](docs/party-bonus-study.md)は前列補正拡張前の記録です。

開発時は [AGENTS.md](AGENTS.md) に従い、検証した機能単位でコミットします。GitHub remote は private を維持します。

以下の編成ボーナス比較は `orchestra-9` 時点の記録です。現在も開始前に編成ボーナス「なし／控えめ／強め／強め・速度比較」を選べます。[ボーナスの倍率と確定タイミング](docs/party-bonuses.md)、[ATB帯と固定陣形](docs/atb-display.md)、[編成と装備を評価するAI](docs/composition-ai.md)を参照。

前列は全職の威力・チェインが各1.25倍。[位置補正](docs/front-row.md)と[同条件で約3倍になったヘッドレス計測](docs/headless-performance.md)を参照。再計測は `npm run sim:bench -- --dir artifacts/new-bench`。

最新の[前列補正あり・12,000戦の比較結果](docs/party-bonus-front-study.md)では、全員前列の攻撃優先は改善しましたが、予告対応AIがなお優勢でした。速度比較用の敵HP倍率は1.40です。

プレイ中の **M／L3／「今のところ」** で場面に印を付けられます。「印の一覧」（Shift+M、休憩中のL3、戦闘結果からも開けます）で感想を残し、約3実秒前・印の瞬間・遭遇開始から再操作できます。選択キャラ・予約・保持対象・補助の表示も復元します。元の記録は残り、印はブラウザ保存とJSONの書き出し・読込に対応します。[使い方と検証の区切り](docs/playtest-loop.md)。
