# ATBを貯めて連続行動へ変換する

実装済みのルールは `orchestra-9`。発動時間と最後の硬直を保ち、同じ技の間だけを短くする。使わなかったATBは保持し、実行中の補充を止める。既定の補充速度は **0.85 ATB/秒**（編成ボーナス適用前）。敵のHP・予告・攻撃間隔・チェイン猶予は変更していない。

## FF13で確認した範囲

2026-09-07に添付テキストの出典を確認した。

- 公式攻略本の公開サンプルのChapter 3「THE VILE PEAKS」では、ATBが2区画貯まった時点での早期実行と、攻撃間の充填待ちでのポーション使用を説明している。[Piggyback公式サンプル、PDFの6枚目](https://www.piggyback.com/us/wp-content/uploads/sites/6/2020/04/FFXIII_E_SamplePages.pdf)
- LewdDolphinの走者ノート（2017-10-15更新）のGaruda戦は、妨害されたら残りの行動列を取り消してATBの再充填を始める手順を記載している。通常充填と行動列の消化が分かれるという理解を支持する実践資料。冒頭のATB Refreshは、初回と、その後12秒経過後のオプティマ変更による全快を別機構として説明している。[Final Fantasy XIII Any% Notes、冊子28ページと3ページ](https://www.scribd.com/document/387491592/speedrun)
- 充填時間と攻撃アニメーション時間を足して一巡とする説明もあるが、こちらはプレイヤー投稿で、公式のフレーム定義として扱わない。[Steam Communityの解説](https://steamcommunity.com/app/292120/discussions/0/2289464731264388118/?l=tchinese)

原作の最後の戻り動作と充填再開の重なり、キャンセル受付のフレームは実機照合していない。本作で薬も補充停止に含めること、終了硬直を残すこと、未使用ATBの保持、武器変更・交代の時間契約は、本作側の仕様である。FF13のATB Refreshは追加していない。

## 実行の契約

| 状態                               | 補充       |
| ---------------------------------- | ---------- |
| 指示待ち、ATB不足で先頭を待つ      | する       |
| 実行保留中で現在の行動が終わった後 | する       |
| 技の発動、同技への接続、終了硬直   | しない     |
| 移動・武器変更・交代の実行         | しない     |
| 薬の発動・硬直                     | しない     |
| 防御効果が持続しているだけ         | 通常どおり |

判定はキャラクター単位。予約が残っているだけでは止めない。通常の行動開始・終了は1/60秒の境界で処理する。次の開始を待つ1 tickには通常の待機充填があり得るが、短縮した接続中には待機を挟まず、補充も入らない。

連結対象は斬撃・射撃・砕光・砕突・砕打・小さな祈り。接続時間は各0.2秒。同じキャラクター・武器・技で、次の技のATBを所持し、対象が有効で、保留や先行する移動・武器変更がない場合に限る。対象の同一性は要求しない。防御・薬・移動・武器変更・交代・2 ATB技は連結しない。

命中から接続時間が経った後、次の開始と支払いが成功した瞬間にだけ通常硬直を置き換える。取消・対象死亡・ATB不足なら命中から数えた通常硬直を継続する。予約の提示だけでは短縮できず、取消で硬直を最初から払い直すこともない。命中済みフラグと、その行動が使う発動・硬直の値をStateへ保持する。

4 ATBから斬撃4回なら、発動0.9秒×4、接続0.2秒×3、最後の硬直1.0秒で5.2秒。初撃を早くしたり、最後の硬直を消したりする処理はない。

## 保留・打ち切りと操作

| 操作                         | キーボード                           | 標準パッド                                   |
| ---------------------------- | ------------------------------------ | -------------------------------------------- |
| 保留／解除して放つ           | H、またはATB帯のボタン               | R3で予約一覧 → 主力技ボタン（PS:△ / Xbox:Y） |
| 未開始の予約をすべて打ち切る | Shift+Backspace、またはATB帯のボタン | 予約一覧 → 薬ボタン（PS:□ / Xbox:X）         |
| 先頭1件を取り消す            | Backspace / Delete                   | コマンド画面の戻るボタン                     |
| 任意の1件を取り消す          | 予約一覧の該当行を押す               | 予約一覧で選択 → 決定                        |

保留中も予約は編集できる。実行中に保留した場合は現在の一手と終了硬直を終えてから待つ。解除後は先頭のコストが貯まり次第開始するので、必ず満タンを待つ必要はない。同じ操作キャラを押し直しても保留を解除しない。別キャラへの交代を指示した場合は保留を解除し、現在の一手の後に1 ATBの交代を実行する。

打ち切りは未開始の予約列を消す。現在の一手・終了硬直・支払い済みATBは戻らず、未使用の残量は残る。独立した一括隊列・オプティマ指示は、従来どおり予約列の取消の対象外。打ち切りで保留設定そのものは変えない。保留中に防御を追加したときは、放つ操作が必要。

例：4 ATBから斬撃の2手目で打ち切れば、残り2 ATBを保持。2手目の発動と硬直を終え、1 ATBを防御・交代に使える。画面は所持ATBと予約コストを別に表示する。予約一覧の「連結予定」は現在の対象・武器・資源での条件付き予測で、時刻は開始ではなく効果発生までを示す。

仲間の基本自動行動も、所持分から2〜3手の同技列を組む。自動回復の後続は対象のHPが83%以上になると取り消す。手動で指定した対象を勝手に振り替えない。交代して操作を受け取ったキャラは、その時点の一手を続け、自動生成した後続だけを解く。

## 実行と予測、保存

`src/sim/execution.ts` の進行処理を本体と `planTiming()` で共有する。発動・硬直、接続の可否、ATB不足待ち、並行した列・武器変更、交代の先頭優先が共通。UI・予告対応AIは通常速度の戦闘秒で効果時刻を受け取る。未来の撃破・被弾・新しい指示は予測しない。編成のATB倍率は予測を呼んだ時点のものを使うため、途中でロールが変わる場合も再評価が必要。

`VERSION` と、連結時間を含めた数値定義の識別の両方で旧ルールを区別する。旧版の途中Stateは直接再開できず、過去の印は従来どおり閲覧と遭遇開始からの比較用に残る。保留・接続済みの2手目・打ち切り・戦術停止を含む入力列の再生が保存Stateと一致することをテストする。

## 測定

再実行は `npm run sim:sequence -- artifacts/任意の未使用ディレクトリ`。既存の測定は上書きしない。[集計と再現条件](atb-sequence-results.json)と[全360戦の入力記録・結果](atb-sequence-runs.jsonl.gz)を保存した。集計にはソースSHA-256、基点コミット、バージョン、実際の定義値を含む。基点コミットに未コミットの実装がある測定なので、コードの同一性はソースSHA-256で確認する。

常時補充／連結だけ／停止だけ／両方を比較し、両方の速度を0.55・0.85・1.00で振った。5戦闘セット、強度1、3方針（rush / balanced / tactician）、2 seed（1307 / 1308）、初期ATB 1 / 4の360戦。装備維持、予約方式queue、編成ボーナス強め、敵条件は固定。初期ATBの変更は第一戦だけで、第二戦は通常の1 ATBへ戻す。常時補充の条件は新しい実行処理内の対照条件で、過去のorchestra-7そのものを実行した結果ではない。

ボーナスなし・敵停止・満タンからの斬撃4回の実測：

| 条件                   | 4発の実行終了まで | 次の満タンまで含む一巡 |
| ---------------------- | ----------------: | ---------------------: |
| 常時補充0.55・連結なし |           7.650秒 |                7.650秒 |
| 連結だけ0.55           |           5.200秒 |                7.283秒 |
| 停止だけ0.55           |           7.650秒 |               14.883秒 |
| 両方0.55               |           5.200秒 |               12.483秒 |
| 両方0.85               |           5.200秒 |                9.917秒 |
| 両方1.00               |           5.200秒 |                9.217秒 |

初期1 ATBで保留せずに4手積むと、両方0.85でも4発の実行終了まで11.117秒。先行入力だけでは満タンからの連続行動にならない。保留して貯める操作を別に持たせる理由である。

初期1 ATBの30戦ずつでは、停止だけ0.55の平均戦闘時間94.22秒に対し、両方0.85は66.74秒、両方1.00は62.63秒。生存キャラの待機時間比率はそれぞれ47.9%・40.7%・37.1%。これは意図的な待ちも含む。勝利は26/30・28/30・28/30で、同程度の勝率でも待ちの長さが異なる。短い比較だけで最適値は確定しないが、0.85を初期設定にする判断と矛盾しない。

固定した追尾予告（2手目開始から2.8秒後に800ダメージ）でも確認した。残HP300の敵なら継続で予告前に倒せ、被害は0。高HPの敵なら継続側は戦闘不能になり、2手目で打ち切って防御した側は被害400・残HP200で生存する。防御成立は打ち切りから2.317秒後。即座に防御が出る仕組みではない。継続と打ち切りの両方に理由があることを、この限定した場面で検証した。

チェインが100%へ戻った回数と過剰回復も記録している。チェインの計数にはブレイク終了を含む。今回の3方針では過剰回復は0だったが、回復AIの一般的な優秀さを示す結果ではない。全員の行動を最適にずらすAI、毎回打ち切る方針と毎回満タンを待つ方針の網羅比較、強度2〜10でのバランス確定は行っていない。今回の実装完了と、長期的な最適戦術の確定は区別する。
