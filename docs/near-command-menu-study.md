# キャラ近傍メニューの比較

2026-09-08、戦闘ルール `orchestra-16`、実装コミット `eedfef5`。今回の確定要件は「3人が同じ列にいても縮小しない」。同じ場面で2案を比較した後、ユーザーが「周囲に展開」を次の土台に選んだ。初期表示を周囲配置へ切り替えた。

## 維持するもの

- 攻撃対象と支援対象、下書きと実行確定、一件取消と画面移動の区別。
- 薬を保持中の支援対象へ直接追加する操作、交代後も予約を保つ規則。
- キーボードの通常のTab・Enter・Space、既存パッドのボタン割当、動きを減らす設定。
- 初期表示は「周囲に展開」。画面の「メニュー位置」で足元案・下の操作盤にも切り替えられる。選択だけで戦闘指示を発行しない。配置の選択は比較用のタブ内設定で、印や戦闘Stateの再生入力に含めない。再読み込み時は周囲配置に戻る。

## 比較する2案

| 候補           | 試す仮説                                                 | 同じにするもの                                                       |
| -------------- | -------------------------------------------------------- | -------------------------------------------------------------------- |
| 足元にまとめる | キャラに近く、まとまった一覧なら技名を追いやすい         | 技・コスト・宛先・操作・色・文字サイズ・ボタンの最低高さ・戦場の余白 |
| 周囲に展開     | キャラを囲む位置関係で、操作する相手と技を結びつけやすい | 同上                                                                 |

両案とも基本技・主力技・防御・救急薬の4ボタン。当初の5ボタンから、ユーザーの「確定ボタンはキャラクターの周囲とは分離」という指示を受けて行動開始を外した。確定はATB・行動予約欄の既存の「行動開始」にまとめ、Hキーとパッドの割当は維持する。周囲案は上2つ・下2つ、足元案は2×2に並べる。

近傍表示中は下の操作盤の基本技・主力技・防御・薬を重複させない。補助・予約・移動・武器変更は下の操作盤から引き続き使える。

初回比較では1101px以上の2候補に各段224px以上を用意した。その後「戦闘画面とATBが一画面に収まる」要件を受け、メニューを置く選択段だけ184px以上を確保する方式へ変更した。ボタンの高さは44px以上、文字サイズは共通。1100px以下では周囲のボタンを縮めず、ATB欄の後ろへ2列に並べる。この幅では2案が同じ配置となり、周囲配置そのものの比較は広い画面で行う。現在の寸法と検証は[戦場とATBの同時表示](battle-viewport.md)を参照。

メニューは実際の操作キャラに付ける。交代を予約しただけでは移さず、交代成立後に移す。攻撃の演出で動く図形には追従させない。メニュー自体の要素と操作ボタンのキーを保ち、列移動や交代でフォーカスを作り直さない。交代後と操作先の切り替え時には、その配置が反映されてから表示範囲へスクロールする。

## 縦幅

変更前の1440×900・交差砲火・全員前列では、戦場高さ350px、各駒38×39pxだった。人数が3人になる条件に、駒の縮小と状態説明の非表示があった。

人数が少ないときから3段分を確保し、駒は64×68pxを保持する。初回はデスクトップで1段136px以上、狭い画面で256px以上を使ったが、一画面に収める調整で段の余白と情報の並べ方を見直した。物理的に収まらない小さな画面では駒を縮めず縦にスクロールする。タイムライン内の縮小プレビューは別の表示として扱う。

## 比較の再現

テストの固定場面は交差砲火、味方3人と敵3人を前列へ配置、味方ATB4、非操作キャラは保留、敵の次回攻撃を999秒とする。ブラウザの時計を固定し、1440×900と1366×600で2候補を同じ状態のまま切り替えて撮影する。390pxでは2列表示とボタン操作を確認する。

再現コマンドは `npm test`、`npm run build`、`E2E_PORT=5188 npx playwright test --workers=3`。近傍メニューだけなら最後のコマンドに `tests/e2e/near-menu.spec.ts` を加える。

キャプチャは `test-results/near-menu/` に出力する。`shelf-detail.png` と `orbit-detail.png` は同じキャラ周辺の比較で、全体画像は `{shelf,orbit}-{1440x900,1366x600,1024x768,390x844}.png`。生成画像はGitへ追加せず、固定場面のテストから再生成する。

単体テスト337件、TypeScript検査を含む本番ビルド、Prettier、`git diff --check` が成功。ブラウザは全体実行で96件成功し、停止時計で描画フレームを進め忘れていた1件を修正したうえで、短いデスクトップの交代確認を1件追加した。近傍メニューの15件を再実行してすべて成功し、重複を除く98件を確認した。

確定ボタン分離の追加変更では、近傍メニューの全15件、本番ビルド、Prettier、`git diff --check` を再確認した。周囲の4ボタンに確定が含まれず、別のATB欄へフォーカスを移しただけでは確定せず、Enterで下書きを一組として確定できることを両案で検証した。

配置の切り替えだけでは戦闘Stateを変えないこと、技・薬の追加と行動開始、対象選択・移動・交代、レイアウト再読み込み、フォーカス保持、画面外へはみ出さないことを検証した。390×844では2人目、1366×600では3人目へ交代しても同じボタンがフォーカスを保ち、コマンド・補助・予約の切り替え後も操作先が画面内へ収まる。実際のブラウザでも3人同列の周囲配置を目視した。

## 次に見たい判断

ユーザーは「キャラを見ながら技を選ぶ感覚」の次の土台として「周囲に展開」を選んだ。周囲配置を採用し、足元案と下の操作盤は比較用に保持する。3人の原寸表示とキーボード・パッドの操作は維持条件とする。今回の選択だけで誤操作率や認識速度の改善が実証されたわけではない。次は継続プレイで「技名を探しやすいか」「戦場にメニューが居続けることが邪魔か」を見る。物理パッドとスクリーンリーダーの実機評価は、ブラウザの自動検証とは別に残る。
