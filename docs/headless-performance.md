中央値で約3.02倍、所要時間67%減。8方針×5セット×強度1/5×標準/全武器の160条件。seed 1307、強めボーナス、最大240実秒、各条件は2連戦まで。起動・import後に8方針の短いウォームアップを行い、各runPolicyの時間を加算した。JSON出力と照合用ハッシュの生成は計測外。リプレイ再生と最終状態の完全一致検証は計測内。Chromeの自動テスト終了後に、プロファイラなしで前後それぞれ別プロセスの3周を測った。

各周の160件すべてで、変更前後の**入力記録と集計結果（最終StateのSHA256を含む）のハッシュが一致**した。反復間も一致。前後で合計960戦のリプレイ一致。過去の前列ルールとは別に、同じorchestra-7内で比較した値である。

## 減らした処理

探索用のCPUプロファイルでは、structuredCloneがサンプル時間の約40%を占め、主に観測と各tickの敵予告のコピーから呼ばれていた。

- 観測は必要な構造を直接コピー。技の対象・倍率、予約対象、武器配列、オプティマ配列、敵予告まで独立したままにする。保持した観測が後から変わったり、AIが本体を書き換えたりしないことを検証した。
- 敵予告の結果集計は、必要な名前と移動可否だけを各tick前に保存。ネストのないログも浅いコピーにする。新規イベントがないtickの全ログ走査を省く。
- 編成判断の8候補は各1回だけ評価。ソート中の繰り返し評価を減らし、同点の順序は維持する。
- 装備探索の1回の呼び出し内では、同じ現役3武器の出力を再利用する。探索候補や評価式は同じ。HPや列、ボーナス条件が変わる次の呼び出しへキャッシュを持ち越さない。

記録・ログ・サンプルの省略、乱数・判断頻度の変更、時間刻みの粗化、リプレイ検証の省略、ワーカ並列化は行っていない。通常のCLIとWeb鑑賞も同じ観測・評価処理を使う。

## 再計測

```sh
npm run sim:bench -- --dir artifacts/new-headless-bench --repeat 3
node --cpu-prof --cpu-prof-dir=artifacts --import tsx scripts/headless-bench.ts --dir artifacts/new-profiled-bench --repeat 3
```

既存receiptへの上書きと、計測中のソース変更は拒否する。変更前はコミット `a1b29f6` の本体に現在の `scripts/headless-bench.ts` を置いて測れる。プロファイラ付き計測は原因探索用とし、速度比較には使わない。
