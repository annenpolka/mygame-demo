# 下書き・行動開始・対象パレット

2026-09-07。追加の添付案に基づく作業記録。実装中。第一段階の実行コアは単体217件・ビルドで検証済み。入力画面・パッドへの接続は次の段階。

1. 下書きと確定列をStateへ分離し、列全体のATB待ちを実行・予測・保存再生に反映する。
2. 対象候補を常駐させ、基本技・主力技・防御をその場で下書きへ積む。
3. 右トリガーを実行、左トリガーを後続取消にし、左スティックと十字キーを分離する。十字キーで選択する代替プリセットも用意する。

実行は一方向の確定操作で、連打による複製や停止は起こさない。未開始の確定列は一組まで。確定済み未実行分と下書きの合計にATBコスト・手数上限を適用する。現在の一手は別枠。後続取消は確定分だけを消し、下書きを保持する。実行中の一手・最後の硬直・未使用ATBは維持する。

手動の対象候補は敵・味方を別に記憶し、仲間AIの集中攻撃対象とは分離する。単体技はID、列技は追加時に示す列を保存する。空の列も選べる。候補変更で既存の下書きや確定列を書き換えない。

検証：実行連打、全コスト待ち、確定列と次の下書き、攻撃打ち切りから防御実行、予約容量、武器変更、対象不在、交代、時間操作、保存・再生・印、予測時刻。パッドは3機種の仮想入力とデジタル選択プリセット、押しっぱなしの非反復を確認する。

第一段階では `draft` / `executeSequence` コマンドと、キャラの `draft` / `sequences`、予約・実行中の `sequenceId` を追加。従来の `enqueue` はAI・比較用の確定予約入力として残す。下書きは実行スケジューラが読まない。待機する確定列は一組、実行中の列との間では終了硬直を省略しない。AI観測へ下書きと列境界のコピーを渡す。数値は維持し、コア変更の識別は `orchestra-10` とする。
