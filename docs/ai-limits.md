# 横向き戦闘UIと、現行AIの攻略境界

この比較は防御0 ATBの `orchestra-1` 時点の記録。下記の数値は旧ルールの実測として保持する。防御1 ATB・硬直ありの `orchestra-3` による再測定は[戦闘テンポとシナリオ傾向](tempo-study.md)を参照。

2026-09-07。実行条件と全強度の勝敗集計は [ai-limits-results.json](ai-limits-results.json) に保存した。6 AIの判断・観測コードは以前の `policies-2` と同一のSHA-256で固定している。

## 画面で試す

`npm run dev` で起動し、開始前の「戦闘セット」と「強度」を選ぶ。元の鐘楼に、各2連戦の4セットを追加した。味方後列 → 味方前列 ｜ 敵前列 → 敵後列の横配置で、仲間3人のHP・ATB・予約を戦場直下に並べている。技の対象は駒・敵情報カード・列見出しから直接選べる。

画面下の「戦闘ログ」を開くと、戦闘別・種類別の絞り込み、名前・技名の検索、最新追従の切り替え、JSON保存ができる。戦利品・結果画面からも読める。セッションで全イベントを収集するため、コアの直近160件より前も残る。状態保存はログも保持し、リプレイ読み込みでは入力列からログを再構成する。古い状態ファイルでは含まれている末尾のログだけが復元される。

## 比較条件と境界の読み方

4セット × 強度1〜10 × 6 AI × 20 seed（1307〜1326）= **4,800ラン**。各ランは2連戦の両方を突破すれば勝利。全滅は敗北、実時間180秒に達した未決着はtimeoutとして別集計。今回50ランがtimeoutだった。リプレイの最終状態完全一致は **4,800/4,800**、拒否入力は **0**。

強度Lの敵HPは `1.30^(L−1)` 倍、ダメージは `1.40^(L−1)` 倍。L5はHP2.86倍・ダメージ3.84倍、L6はHP3.71倍・ダメージ5.38倍。列・編成・攻撃周期・予告時間は強度を変えても同じ。ATB0.85、観測間隔0.25実秒、反応待ち0.35実秒、敵攻撃倍率設定1、戦間装備更新は全AI共通で以前と同じ。

以下の「90%以上」は今回の20 seed中18勝以上という**観測上の基準**。未測定seedでの勝率や最適戦略の証明ではない。全員生存は勝利条件に含めず、第一戦で倒れた仲間も従来どおり戦間に全回復する。表中 `T` は勝てなかったランのうちtimeoutの件数で、残りは全滅。

## ログから読めた負け方

### 双盾：防御が間に合っても耐えられない

L6・seed1307の予告対応AIは、4.97戦闘秒でアルトに防護を張ったが、5.02秒の左盾で672ダメージ、5.62秒の右盾で残HP628を失った。回復構成への変更は5.25秒。34.70秒に全滅した。

同じ条件の時間操作AIは、3.37戦闘秒に退避指示を出し、3.98秒に後列へ到着した。左右の薙ぎ払いは5.02秒・5.61秒に空振り。74.93戦闘秒／80.93実秒で2連戦を突破した。判断ログとイベントの順序から、スローで反応を待った結果、円弧斬りの開始前に移動を差し込めたことが差につながっている。

参照：[予告対応の敗北](../artifacts/ai-limits/traces/bulwark/level-6/tactician/defeat/trace.md)、[時間操作の勝利](../artifacts/ai-limits/traces/bulwark/level-6/focus/victory/trace.md)。

### 交差砲火：攻撃予約中の防御を差し込めない

L6・seed1307では、両AIとも4.62戦闘秒に衛兵の薙ぎ払いでアルトがHP1300を失う。アルトは直前まで円弧斬りを実行しており、現行AIの `usable` 判定が実行中の人物への予約を避けるため、防御を予約しなかった。コア自体は実行中でも次の防御を予約できる。両列の予告があるため列退避も選ばれない。時間操作AIでもこの衝突は解けず、両者20 seedすべてで敗北した。

参照：[予告対応の敗北](../artifacts/ai-limits/traces/crossfire/level-6/tactician/defeat/trace.md)、[時間操作の敗北](../artifacts/ai-limits/traces/crossfire/level-6/focus/defeat/trace.md)。

### 追撃：回復・薬が残り続ける条件ではなくなった

L6・seed1307では、両者とも救急薬3個を消費して第二戦で全滅した。予告対応は累計回復13,170、時間操作は12,030でも押し切られた。時間操作側の集中力消費は2戦累計192。空振りは両者0回で、列移動だけでは被害を避けられないセットになっている。

L6の勝利seedは、予告対応が1316・1322、時間操作が1325。時間操作を加えた方が必ず勝つ関係ではない。ただし20 seedで2勝対1勝なので、この差だけから一般的な優劣は断定しない。

参照：[予告対応の敗北](../artifacts/ai-limits/traces/pursuit/level-6/tactician/defeat/trace.md)、[時間操作の敗北](../artifacts/ai-limits/traces/pursuit/level-6/focus/defeat/trace.md)。

### 灰雨：勝てる場合でも脱落を伴う

L6・seed1307の予告対応は、第二戦66.33戦闘秒にアルトとセナが同時に倒れ、72.15秒で全滅した。同seedの時間操作は第一戦でセナが倒れたが、戦間回復を経て、第二戦はアルトとセナが生存したまま突破した（113.66戦闘秒／123.78実秒、合計2回の戦闘不能）。「突破できた」は無傷・安定を意味しない。

20 seed全体では予告対応5勝、時間操作4勝。スローによる行動順の変化と追尾対象のばらつきを含むため、代表例の勝利だけで時間操作の優位を結論づけない。

参照：[予告対応の敗北](../artifacts/ai-limits/traces/attrition/level-6/tactician/defeat/trace.md)、[時間操作の勝利](../artifacts/ai-limits/traces/attrition/level-6/focus/victory/trace.md)。

## 再実行

```sh
# 同じ4,800ラン。AIの判断・観測コードのSHA-256が変わっていれば停止する
npm run sim:limits -- --seeds 20 --seed 1307 --dir artifacts/ai-limits

# 特定の条件を深掘りする
npm run sim -- --policy focus --set bulwark --level 7 --seed 1307 --dir artifacts/bulwark-l7

# 記録した入力を完全再生する
npm run sim -- --replay artifacts/ai-limits/traces/bulwark/level-6/focus/victory/replay.json
```

`artifacts/ai-limits/results.json` に全ラン、`boundaries.json` に勝敗集計、`traces/<セット>/level-N/<AI>/<勝敗>/` に各条件で最初に観測した勝利・敗北・timeoutそれぞれのイベント全文・判断理由・サンプル・入力リプレイがある。生成ログはGit対象外だが、条件・ハッシュ・集計は本ドキュメントと `ai-limits-results.json` に残している。

予備実行 `ai-limits-pilot` は加算式の強度で360ラン、`ai-limits-pilot-geometric` は今回採用した倍率式の5点で360ラン。前者では強いAIの失敗が出なかったため、倍率式にして測定範囲を確定した。上の4,800ランには予備実行を混ぜていない。調整後の戦闘定義・強度・検証コードは全4,800ラン中固定した。

## 表示・動作の検証

- 単体・統合テスト62件：既存ルール、160件を超えるログ保存、状態／リプレイ復元、戦闘セットごとの攻撃対象・強度・完全再現を検証。
- Chrome E2E 9件：2連戦・編成更新・ポーズ、横配置と直接対象指定、ログ検索・保存、戦闘セット変更、390pxでの3敵表示と結果ログを検証。
- 1440×900の戦闘画面では、戦場・仲間・技・隊列・ログ入口が画面内に収まることを座標でも確認。390×844では横スクロールなし。撮影画像を目視確認し、通知の大きさ、3敵の並び、結果ダイアログのスクロール範囲を修正した。
- TypeScript／ViteビルドとPrettier検査を通過。最終版を新規ブラウザタブで実操作し、ランタイムエラーなし。
