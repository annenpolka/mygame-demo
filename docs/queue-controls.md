# 行動予約・パッド操作とAI比較

2026-09-07。人間も技・移動・武器変更を各人6手まで積めるようにした。操作は末尾への追加と取消。実行中の技と、未実行の予約は別に表示する。

## 操作の規則

「仲間 → 行動 → 対象」の順に選ぶ。基本技・主力技・防御・薬は同じ対象確認の流れで積む。「移動」「武器変更」は行動を選ぶと積まれる。仲間を替えても予約は保持する。

右の一覧には順番、行動名、対象、開始までのおおよその戦闘秒を表示する。時間は現在のATB・実行中の技・既存の予約から計算した目安で、敵による中断や対象の死亡を予測しない。スロー中の実時間とも異なる。6手の上限に実行中の技は含まない。

個別取消はその手だけを消し、残りを同じ順に実行する。全部取消も実行中の技は中断せず、ATBを返さない。武器変更を消して使えなくなった後続の技も解除し、理由をログに残す。対象が倒れた技は飛ばす。ATB不足なら先頭の技を待ち、薬は全員の予約数が残数を超えないようにする。

例：円弧斬り → 防御 → 救急薬 → 後列へ移動 → 盾槍に変更 → 護りの誓い。盾槍を予約した時点で、末尾に積める技が盾槍の技に替わる。2手目の防御を取り消しても、薬以降の順は変わらない。

一括隊列・オプティマは現在の技が終わった後、個別予約より先に反映する。変更後に使えなくなる技は解除する。旧AIと保存済みリプレイには従来の1件上書きコマンドを残し、互換性を検証した。

## ゲームパッドと画面確認

Xbox、PlayStation、Switchの標準配置を認識し、ボタン表記を切り替える。Switchの決定は右側のA、XboxとPSは下側のA／×。独自配置ではボタン、横軸・縦軸、軸反転を登録し、機器IDごとにブラウザへ保存する。

方向キーと左スティックで画面内を移動し、決定で選ぶ。肩ボタンで仲間を切り替える。設定や戦利品画面では肩ボタンで項目間を移る。予約の取消は該当ボタンを選んで決定する。押しっぱなしは方向移動だけをリピートし、技の連続投入を防ぐ。接続・復帰時の押しっぱなしを無視し、切断時は休憩ポーズに入る。

実装は[Gamepad APIの標準配置](https://w3c.github.io/gamepad/#remapping)に従い、フレームごとに状態を読み直す。ブラウザに公開されない機器は操作できない。実機は未接続で、検証は隔離したChromeに仮想パッドを注入して行った。振動は実装していない。

1440×900の戦闘画面で横の4列、行動欄、6手の一覧、閉じたログが見渡せることを確認。390px幅では欄を縦に送り、横スクロールが生じないことを確認した。画面画像は `test-results/` に出力する。

## 比較条件

4セット × 強度1〜10 × 2方針 × 3予約方式 × 20 seed = **4,800ラン**。各ランは同条件の2連戦。seedは1307〜1326、上限180実秒、観測周期0.25実秒、反応待ち0.35実秒（周期により実効0.5秒）。人間の反応時間を実測した値ではない。

| 方式   | 行動中の予約               | 先読みの深さ | 実装                         |
| ------ | -------------------------- | ------------ | ---------------------------- |
| legacy | 旧判断ロジックでは行わない | 次の1手      | 従来コードを固定             |
| next   | できる                     | 次の1手      | 新しい予約判断               |
| queue  | できる                     | 最大3手      | nextと同じ判断、深さだけ変更 |

新しい判断には、攻撃予約の取消後に防御・薬を積む処理と、予約済みの行動・ATB待ちを含む到達時間の見積もりがある。したがってlegacyとの差を「予約枠の増加だけの効果」とは扱わない。nextとqueueは深さのみの比較である。残りの4方針の判断は今回変更していない。

未来の敵タイマーや乱数状態を見せず、人間と同じ追加・取消コマンドを使用する。敵HP、ATB、ダメージ、武器報酬などのルールは変更していない。

## 実際に見た戦闘

交差砲火6、tactician、seed1307を比較した。

- legacyは69.38戦闘秒で全滅。薬を使わず、累計与ダメージ2,235、被害7,920。
- nextは94.85秒で2連戦勝利。薬3個、累計与ダメージ33,230、被害13,196。実行中に15回予約した。
- queueは105.43秒で勝利。薬3個、被害16,281。実行中に19回予約し、最大3手まで積んだ。

3.25秒の予告対応では、queueがアルトの攻撃3手、リネの攻撃3手、セナの攻撃1手を取り消し、それぞれ防御を追加した。9.00秒にはアルトとリネの技が実行中のまま、後続攻撃を消して防御を追加。10.50秒にはアルトの攻撃3手を消し、HP140のセナへ救急薬を積んだ。並べ替えや実行中の技の取消は使っていない。

queueの時間切れはseed1311と1313。1311の終盤はセナが衛兵へ33〜35ダメージの攻撃を繰り返し、180秒で打ち切られた。これは全滅ではない。複数手の予約が攻撃継続を助けても、消耗後の火力を保証しない例になっている。

設計上は、**次の1手を実行中に積めること**の価値と、**何手まで見通して積むか**の判断を分けて考えるのがよさそうだ。予告が変わると取り消す手間が増えるため、人間の上限6手を常に埋める前提にはしない。この解釈は今回の限定した方針・敵・seedからの推測で、人間の操作評価は別途必要になる。

## 再現と検証

```sh
npm test
npm run build
npm run test:e2e
npm run sim:queue -- --seeds 20 --seed 1307 --dir artifacts/queue-study
```

全4,800ランの最終状態が完全一致リプレイを通過し、拒否入力は0件。旧AIの1,600ランは以前の保存結果と最終状態ハッシュが一致した。

全強度の集計と実装ハッシュは [queue-study-results.json](queue-study-results.json)。個別結果は `artifacts/queue-study/results.json`、代表戦闘は `traces/<set>/level-<level>/<policy>/<mode>/<outcome>/` に保存し、理由付き判断・全イベント・リプレイ・Markdownを読める。

個別結果の `cancellations` は武器変更などによる自動解除件数を表す従来の指標。今回の手動取消は `decisions.jsonl` の `removePlan` 指示と全イベントの「取消」で確認する。

単体テストでは実行中の追加、6手上限、途中取消、武器依存、移動→武器→技の順序、薬の共有残数、対象死亡、戦闘終了時の消去、JSON保存／復元、入力記録の完全再生を検証する。Chromeでは3系統のパッドで開始・積み込み・取消・仲間切替・休憩・切断、独自割当の保存、PCと携帯幅の表示を検証する。実機の接続・各OSとブラウザの組み合わせは未検証。
