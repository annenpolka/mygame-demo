# 個体選択とロール別AI

2026-09-07。`orchestra-12`。対象操作と味方AIの対象選択を変更した。ATB・技の威力・硬直・敵の数値は変更していない。

## 手動の対象

2026-09-08の入力更新では、左スティックの上下は同じ列の上・下、左右は隣の列へ移動する。右スティックの左で味方、右で敵へ切り替える。列見出しは選択できない。追加ボタンや同時押しは増やしていない。

同じ敵を選んだまま、基本技・主力技を続けて積める。斬撃はその敵のID、円弧斬りは**追加時にその敵がいる列**を保存する。範囲技のボタンには「敵前列・2体」のように、予約する列と現在の人数を表示する。味方への列技も同じ規則。

範囲技は予約後に対象の移動を追わない。着弾時、その保存した列にいる生存者へ作用する。列の固定時点や戦闘計算は従来どおり。対象が死亡した場合は選び直しを求め、既存の下書きや確定した行動の対象を自動変更しない。

## 仲間AI

共有の集中攻撃ボタン・マーカー・Stateの `target`・`target` コマンドを削除した。対象候補を見比べる操作からAIへ指示は送らない。時間操作に使う「集中力」とAI方針「時間操作併用」は別機能なので継続する。

| ロール・技 | 主な判断 |
| --- | --- |
| A | 一撃で倒せる敵、発動までブレイクが残る敵、Bが伸ばしているチェインの維持を重視する。後列防護と武器・編成・位置補正も見込む。 |
| B | 倒し切れる敵を見ながら、未ブレイクで閾値に近い敵を優先する。同程度ならAが行動中・予約中の対象に合わせる。Aがブレイクを削っている間に別の敵を崩せる。 |
| D | 防護が不足している生存者から、間に合う攻撃予告、HP、前列の露出を評価する。常に前列の先頭へ掛ける挙動を廃止。 |
| S | HP83%未満を対象とし、HP不足と他の味方が発動中の回復を考慮する。同じ負傷者への回復が重なる無駄を減らす。 |
| 引き寄せ・押し出し | 踏ん張りや重装を確認し、実際に移せる相手と中断できる予告を評価する。 |
| 範囲技 | 列内の生存者に対する評価を合計する。単体の代表者だけで決めない。 |

`src/sim/targeting.ts` の純粋関数を自動行動と編成適応AIで共有する。観測できるHP・列・チェイン・予告・味方の行動だけを使い、RNGや非公開の敵タイマーは参照しない。同点はID順、列は前列を先にする。方針AIの武器・回復・退避判断はそれぞれ維持する。

発動済みの `Action.target` は固定する。自動行動が作った `auto` の後続は、次の一手を開始する境界で選び直す。対象が死亡しても、別の生存者へ連続技を接続できる。手動の下書き・確定列や、方針AIが明示的な戦術として予約した対象は、後から一括上書きしない。AIの現在の対象は駒の行動表示で確認できる。

- 旧 `orchestra-11` の途中Stateと廃止コマンドは取り込まない。列候補を含む旧版の印は閲覧でき、遭遇開始からの比較に使える。

共有標的の廃止と状況別判断によって、均衡型・編成適応型の攻撃は短時間になったが、被害は増えた。自動行動任せの所要時間はほぼ同じ。この比較から高難度や全方針の優位性は主張しない。従来の実験ファイルは各旧版の結果として残す。

再現は `npx tsx scripts/targeting-study.ts /tmp/targeting-study.json`。変更前は `97afbf3` のチェックアウトに同スクリプトを配置して実行する。条件、各ランの要約、Stateハッシュ、対象コードのSHA-256は [targeting-results.json](targeting-results.json) に記録した。`baseCommit` は測定開始時のHEADなので、変更後のコード識別には併記したSHA-256を使う。
