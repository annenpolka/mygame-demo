# パッド初回認識の調査（2026-09-08）

対象: `3d02cc6`、Chrome の `http://127.0.0.1:5173/`、待機画面。
実機は `DualSense Edge Wireless Controller (STANDARD GAMEPAD)`。
USB / Bluetooth の接続方法と Chrome のバージョンは未確認。

## 今回確認できたこと

ブラウザが機器を公開する前は、ゲームに接続情報が届かない。公開後の検出は今回の観測では正常だった。
さらに `PadReader.read()` は接続を初めて観測したときの押下を保持済みとして扱い、操作を発行しない。
そのため、接続を成立させた一押しと、ゲームを操作する次の一押しが分かれる。

Gamepad API は、初回のパッド操作を観測するまで機器を公開しない仕様を持つ。
接続済みの機器について、フォーカスされたページでボタンまたは軸を操作すると接続イベントが届く。
参照: [W3C Gamepad](https://www.w3.org/TR/gamepad/#dom-navigator-getgamepads)、
[MDN: Connecting to a gamepad](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API#connecting_to_a_gamepad)。

## 実機の観測

開発時のみ有効な一時ログで、接続イベント・各フレームの接続一覧の変化・入力受付条件・発行操作を記録した。
`ts` はブラウザ内で取得した `Date.now()`。ユーザーがゲーム画面をクリックしてボタンを押す手順を試し、表示が変わったことを確認した。

| ts            | 観測                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| 1788818387170 | 表示・フォーカスとも有効。APIあり、secure context。機器一覧は `[null, null, null, null]`、例外なし。 |
| 1788818451863 | DualSense Edge の `gamepadconnected`。index 1、mapping は `standard`。                               |
| 1788818451868 | 次の観測で同じ機器を選択。ボタン13が押下中、入力受付は有効。操作発行はなし。                         |
| 1788818451968 | ボタンが離れた状態を受信。接続と入力受付は引き続き有効。                                             |

接続イベントからポーリングでの検出までの間隔はこの一例で 5 ms。
物理ボタンを押してからの遅延、平均値、上限を測定したものではない。
画面の「🎮 パッド」が「🎮 PS」へ変わったことを DOM とユーザーの返答で確認した。

## 仮説の判定と限界

- H1: ブラウザから未公開だった状態は確認。画面をクリックして押下する手順で接続できた。ただし、元の失敗時にフォーカスが外れていたかは未確認。
- H2: 初回押下の抑制は確認。実機で操作が発行されず、`PadReader` 単体でも「未検出 → 押下中に初検出 → 離す → 再押下」で最後だけ操作を発行した。
- H3: 別機器を先に選ぶ問題は今回の観測では該当しない。機器は1台で、空の index 0 を飛ばして index 1 を選択できた。
- H4: API例外・非標準マッピング・再入力待ちによる無効化は今回の観測では該当しない。

認識まで何度も押す必要がある現象そのものは今回再現していない。Bluetooth、OS、ブラウザ内部の問題を否定する証拠ではない。
認識表示が変わったかと、ゲーム操作が効いたかを分けて調べる必要がある。

## 確認手順と検証

1. 接続済みのパッドがある状態でページを読み込む。
2. ゲーム画面をクリックし、パッドのボタンを一度押して離す。
3. 右上が機種表示に変わるか確認する。
4. 次のボタン操作が受け付けられるか確認する。

`npx vitest run tests/gamepad.test.ts` は26件成功。
接続・再接続時の押しっぱなしを再発行しない既存テストを含む。
`npm run build` と `git diff --check` も成功。
接続後の操作は従来どおりで、今回、認識処理・操作ルールは変更していない。
一時的な計測コードは観測結果とユーザー確認を得て除去した。
