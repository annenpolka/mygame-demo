## 操作の参考と、このゲームへの適用

『ペルソナ5』の[公式PS4マニュアル・戦闘操作](https://atlus.com/persona5/manual/ps4/img/015.jpg)と[コマンド説明](https://atlus.com/persona5/manual/ps4/img/040.jpg)を確認した。技・防御・アイテムを対応するボタンから開き、技の後に対象を選ぶ構造を参考にした。『メタファー：リファンタジオ』については[アトラス公式試遊レポート](https://www.atlus.co.jp/news/25345/)に、対応ボタンを覚えてコマンド操作する体験と、操作性を重視したGUIの説明がある。

このデモでは、4つのボタンの物理位置に合わせて基本技・主力技・薬・防御を置く。メニューの見出し、対象の強調、画面下の操作案内で「今どのボタンが何をするか」を示す。紺・象牙色・金の既存配色とCSS/SVGを使った。

リアルタイムATBと各人6手の予約に合わせ、対象を決定した後も同じ対象を保持する。決定を離して押すたびに1手追加し、戻るでコマンド画面へ戻る。防御は1押しで予約の末尾へ入る。実行中の技や、それより前の予約を追い越さない。

## 操作

既定の割当は[READMEの機種別一覧](../README.md#ゲームパッド)を参照。

| 場面           | 操作と結果                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------- |
| コマンド       | 4ボタンから基本技・主力技・薬・防御。方向は↑全員、←移動、→武器、↓取消                          |
| 対象選択       | 方向で対象、決定で1手追加。同じ画面・対象を保持。対象は仲間・技ごとに記憶                      |
| 移動・武器変更 | 方向で選び、決定で末尾に追加してコマンドへ戻る                                                 |
| 全員への指示   | 左右でオプティマ／一括隊列、上下で選択、決定で指示。個別隊列のみのモードでは一括隊列は利用不可 |
| 予約取消       | 最後の手を初期選択。上下で選び、決定で個別取消。薬のボタンで未実行分を全取消                   |
| 戦闘ログ       | 上下で履歴を読む。決定で最新の6件へ戻る                                                        |
| 各戦闘画面共通 | 肩ボタンで仲間。トリガーでスロー／戦術停止。戻るでコマンドへ。Menu系で休憩                     |

予約は追加と取消だけで扱う。一括隊列・オプティマの優先規則、対象死亡や武器不一致による予約解除は既存ルールのまま。移動や武器変更も6手に含み、将来の武器に変更する予約を積むと、その武器の技を続けて選べる。救急薬は全員分の予約を差し引いた未予約数を表示する。

## 画面と入力の境界

- パッド用画面では、仲間3人を上段、直接コマンドと予約を下段に置く。1440×900で横の戦場、敵の状態、HP・ATB、6手、集中力、閉じたログまで表示する。
- 携帯幅では縦に送り、選択したコマンド欄・取消する手へ自動スクロールする。横の4列は維持する。
- 通常の戦闘入力は `src/input/battle-pad.ts` の選択状態で解釈する。ページ上の無関係なボタンへフォーカスが飛ばない。出発前・設定・戦利品・実験室は従来のナビゲーションを使用する。
- 対象や予約は安定したIDで選ぶ。選択中の対象が倒れたり予約が実行された直後は、消えた項目への決定で別の手を誤実行・誤取消しない。
- 接続・復帰時の押しっぱなしを無視し、方向だけリピートする。入力割当の登録中に技は発動しない。旧ブラウザ設定は新形式へ移行する。
- 設定の「操作画面」で自動・パッド用・マウス用を選べる。マウスやキーボードでも専用画面を利用できる。
- メニュー中も戦闘と集中力の時計は通常の規則で進む。休憩は戦場を覆って両方を止め、切断・別タブへの移動でも休憩する。

## 戦闘エフェクト

`src/client/effects/events.ts` が解決済みのイベントから描画用の手掛かりを作り、`BattleEffects.tsx` が戦場の駒に重ねる。確定前の予約から命中を推測しない。

| 出来事                 | 表示                                                     |
| ---------------------- | -------------------------------------------------------- |
| 斬撃・射撃・魔法・打撃 | 対象位置の斬線・矢・光輪・衝撃。攻撃元が分かる技には軌跡 |
| 被ダメージ             | 赤い衝撃、実際のダメージ値                               |
| 回復                   | 緑の光と十字、実際の回復値                               |
| 防護                   | 盾の形、効果が続く間の枠と残り秒数                       |
| 移動・押し引き・退避   | 列をまたぐ矢印と移動の表示                               |
| 武器変更               | 回転する四角と変更表示                                   |
| ブレイク               | 放射状の破裂とBREAK表示                                  |
| 構え中                 | 残り準備時間に対応した駒のリング                         |

技の種類は直前の同じ行動者の行動イベントと現行の技定義から分類する。ダメージ・回復値はイベントの実値を使う。持続状態と構えの進行は現在状態から描く。同時に当たった数値をずらし、技名は同じ対象に1つだけ表示する。

演出の進行は戦闘時刻で計算するため、スロー・戦術停止・休憩に同期する。通常は0.8戦闘秒、ブレイクは1.3戦闘秒で消える。動きを減らす設定では軌跡の飛翔、拡大・回転を抑える。描画要素は入力を遮らない。

## 検証

`npm run build`、`npm test`、`npm run test:e2e` で確認する。単体88件。Chromeは既存の戦闘E2E 9件と、操作・エフェクトのE2E 11件を確認した。

パッド3系統について、マウスなしで開始 → 技と対象 → 連続追加 → 個別取消 → 仲間変更 → 防御 → 武器変更と変更後の技 → ログ → 休憩 → 切断を通した。押しっぱなしで重複追加されないこと、独自ボタン・軸設定の移行と保存、一括指示、携帯幅で6手の取消まで操作できることも検証した。

エフェクトはコアが返すダメージ・ブレイク・回復・防護・強制移動・武器変更と照合し、戦術停止でSVGの進行が止まることをブラウザで確認した。既存の2連戦から勝利まで、ログ、リプレイ、編成変更も回帰確認した。実機の接続と従来操作はユーザー確認済みで、改修後の操作は仮想パッドでの検証。
