# AI鑑賞のフレームを書き出す

`npm run record:ai -- --out artifacts/recordings/ai-watch` で、標準設定の2連戦を等速・1920×1440・60fpsの音声付きMP4へ書き出す。Chrome、`ffmpeg`、`ffprobe` が必要。既存ブラウザを操作せず、一時プロファイルの専用Chromeとポート5194のViteを起動し、終了時に閉じる。

短い確認用には `--seconds 3` を加える。省略時は戦闘結果まで録画し、結果を2秒保持する。安全上の上限300秒に達しても結果が出ていなければ、全体録画を完了とは扱わずエラーにする。

## 時間と画像

録画用の `?capture=1` ではAppの通常のrAFによる戦闘更新を止める。録画側が1コマごとに既存の `WatchPlayer.advance(session, DT)` を1回だけ呼ぶ。`DT = 1 / 60`、AI速度は1倍で、戦闘中はtick差が必ず1になることを検査する。通常の起動や戦闘ルールは変更しないため、ルール版は `orchestra-16` のまま。

Reactを同期更新した後、戦闘を止めたままブラウザの描画フレームを2回待って、列や演出の位置測定を反映する。JPEG取得とエンコーダーへの書き込みが終わってから次のコマへ進む。処理が重い場合は書き出し時間が延び、動画のコマを捨てない。戦利品の待ち時間と結果画面の静止は意図的な保持。

駒・攻撃・被弾・粒子の演出は元の戦闘Stateによる描画を使う。録画用CSSでは壁時計で動く装飾アニメーションとtransitionを無効化し、戦闘エフェクトを消す「動きを減らす」設定は使用しない。

## 音と検証

既存の `BattleSound.observe` が選ぶ効果音を動画フレームの時刻で収集する。同じ `SOUNDS` の波形・包絡・連打制限・同時24音の上限を使い、OfflineAudioContextで48kHz・monoのPCM WAVを生成する。動画へAACとして合成するので、書き出しにかかった実時間に音が引き延ばされない。

- `frames.jsonl` は各コマの番号、動画時刻、tick、戦闘時刻、遭遇、画像SHA-256を保持する。
- `replay.json` と `final-state.json` は入力再生の終端Stateが完全一致することを検査する。
- 独立したSessionとWatchPlayerを同じDTで進め、終了Stateと判断回数が一致することを検査する。
- 完成MP4をffprobeでデコードし、画像数と動画フレーム数、60/1のフレームレート、全PTSが `frame / 60` と一致することを検査する。
- `manifest.json` はGit HEAD、ソースSHA-256、ルール版、設定、AI方針、画面寸法、フレーム数と検査結果を残す。

成果物は指定先の `ai-watch.mp4`。`picture.mp4`、`sound.wav`、音の時刻一覧、確認画像も保持する。出力先の `artifacts/` はGit対象外とし、動画本体をリポジトリへプッシュしない。
