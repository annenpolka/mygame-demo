# 6種類のAIを実行して分かったこと

2026-09-07。戦闘ルール`orchestra-1`、AI`policies-2`、実行器`runner-1`。

主比較540ラン、機能を外す比較240ラン、反応時間比較180ランの計960実行。seedは1307〜1336、各ランは既存の2連戦です。追加比較では対照条件を再利用しているため、960個の異なるシナリオではありません。960件すべてで入力からのリプレイと最終状態が一致し、拒否されたコマンドは0件でした。

主比較は約3.64秒、追加比較は約2.04秒で終了しました。この処理時間には実行・リプレイ検証・代表ログの書き出しが含まれます。以下の「実秒」はゲームの実時間側の時計であり、CPU上の処理時間とは異なります。

## 同じ装備と敵で比べる

全AIに初期装備と武器更新を共通適用。観測周期は0.25実秒。予告対応系には0.35実秒の反応待ちを設定し、次の観測で指示するため実効0.5秒です。未来の乱数・未予告の行動タイマーは渡していません。ただし数値は内部精度で、複数キャラへコアコマンドを直接発行します。人間の操作負荷やクリック精度の検証ではありません。

標準条件では全AIが30/30で2戦とも勝利しました。時間・被害は2戦合計の平均です。

| 自動行動任せ |  49.25 | 49.25 |      3,122 |        0.0 |             15/30 |

## 引き寄せと列攻撃が攻撃効率を変えている

予告対応AIの代表例（seed 1307、標準条件）は、次の順で行動しました。

1. 0.00秒にABBへ切り替え、砲術師を標的にする。
2. 0.50秒に引き寄せを予約。1.73秒に砲術師が前列へ移動し、衛兵の後列防護から外れる。
3. 1.75秒に円弧斬りと星の雨を予約。3.27秒の円弧斬りが衛兵へ162、砲術師へ233ダメージ。次の星の雨も両方に命中する。
4. 前列薙ぎ払いを見て3.75秒にアルトへ後退指示。4.35秒に移動を終え、5.02秒の薙ぎ払いは空振りする。
5. 第一戦を12.12秒、2戦合計を25.47秒で終える。被害は第二戦の防御した押し込み斬り125だけ。

この例では引き寄せは予告前に使われています。引き寄せによる詠唱中断は起きておらず、実際に働いたのは防護解除と列攻撃の準備です。敵の予告中断はブレイクによるものでした。

同じ予告対応AIから一つずつ機能を外した結果も確認しました。

| 標準条件・30 seed      | 戦闘秒 | 被ダメージ |
| ---------------------- | -----: | ---------: |
| 全機能                 |  25.29 |        125 |
| 引き寄せを使わない     |  33.70 |        125 |
| 手動の列攻撃を使わない |  38.11 |        241 |
| 列退避・防御を使わない |  24.26 |        706 |

今回の2遭遇では、引き寄せと列攻撃を使えることが短縮に寄与しています。退避・防御を外すと標準条件では約1秒速くなる一方、被害は増えます。敵攻撃3倍では退避・防御ありの被害375に対し、なしでは2,846でした。安全を取る操作には攻撃時間の代償もあります。

## 全員前列・全員後列の結果には差がある

攻撃優先AIは全員前列へ出し続けます。敵攻撃3倍・seed 1307では5.02秒の前列薙ぎ払いで3人が各750ダメージを受け、10.83秒の次の薙ぎ払いで全滅しました。敵を崩す速度だけでは、残った衛兵の攻撃に対処できていません。

後列維持AIは約65秒かかりますが、敵攻撃3倍でも30/30で生存します。退避操作を連打しなくても成立する戦い方が、現在の敵配置と回復性能の範囲では残っています。一方で、回復役を常駐させるぶん攻勢が遅くなります。

## スローは反応の遅さを補えるが、実時間は増える

敵攻撃3倍で、予告対応と時間操作併用だけを、同じ反応待ちで比較しました。

| 反応待ちの設定 | AI             | 戦闘秒 |  実秒 | 被ダメージ | 集中力消費 |
| -------------- | -------------- | -----: | ----: | ---------: | ---------: |
| 0秒            | 両方が同じ結果 |  24.52 | 24.52 |        375 |          0 |
| 0.35秒         | 予告対応       |  25.29 | 25.29 |        375 |          0 |
| 0.35秒         | 時間操作併用   |  24.52 | 26.77 |        375 |         36 |
| 1.25秒         | 予告対応       |  24.95 | 24.95 |      1,142 |          0 |
| 1.25秒         | 時間操作併用   |  24.53 | 30.15 |        375 |         54 |

反応待ち1.25秒では、スローを使う側の被害が少なくなりました。判断遅延のある条件で、実時間と集中力を払って戦闘時間を買えることは確認できています。待ち時間ゼロでは両AIは同じ入力・同じ最終状態となり、スローを使う必要はありません。

時間操作併用AIは安全な列への予告でもスローを使う単純な実装です。標準条件では予告対応より実時間が約1.5秒長く、30 seedすべてで武器変更に伴う予約解除も1件ずつ出ました。スローを使えば一律に優れたプレイになる、という結果ではありません。

## ログから見つけて直したAIの問題

最初の実装は列技を「ATBが2区画貯まった後、キャラが待機中なら指示」していました。しかし仲間のオートは2区画に達すると基本技へATBを使うため、AIが観測する頃には不足していました。列攻撃を意図していても、実際の技使用数は0でした。

1区画以上の待機中に次の列技を予約するよう変更しました。最終版の予告対応AIでは、標準条件30 seedで円弧斬り240回、星の雨171回、一斉射69回が実際に開始されています。意図と実行の両方を保存して確認する必要があります。

## まだ分からないこと

- 2遭遇とも「前列へ集めて列攻撃」が強い相手です。今回の結果だけで、他の敵や武器に対しても予告対応AIが優れるとは言えません。
- 入手後の装備更新は共通固定です。装備を選ぶAI、編成プリセットを作るAIは今回実装していません。入れ替えた槌を使うプリセットはどのAIも選ばず、槌技の実行は0回でした。軍旗も持ち込まれていません。
- 主比較の予告対応系は回復・救急薬も不要でした。救援に追われる局面の比較は足りていません。
- 手動の範囲技予約で大きな差が出ています。人間のUIで同じ連携が無理なく使えるか、個別操作の義務にならないかは別に遊んで確認する必要があります。
- 自動行動の標的選択、列攻撃の威力、敵の構成など、戦闘バランス自体はこの作業では変えていません。
