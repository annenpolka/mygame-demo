# 手動操作・戦場内の対象選択・AI鑑賞

> 現行の手動操作は **`orchestra-14`** の[二重対象・直接操作・アイコン表示](dual-target-controls.md)と[READMEの操作表](../README.md#操作)を参照してください。以下は `orchestra-7` 等の改修記録で、古い保留・対象選択・武器・時間操作の手順を含みます。AI鑑賞の説明と過去の検証値も、その時点の記録として保持しています。

以下の保留操作・薬ボタン・入力手順は、それぞれの改修時点の記録。

2026-09-07、当時のルール `orchestra-7`。起動は `npm run dev`。

技は発動と硬直を分けて表示する。硬直中は追加・取消が可能だが、次の技・移動・武器変更は待機する。ATB毎秒0.55、敵予告3.2〜4.8秒などの数値と測定結果は[戦闘テンポとシナリオ傾向](tempo-study.md)を参照。

## 防御と操作中の仲間

防御は1 ATBを実行開始時に消費する。準備0.4秒の後、6秒間自分の被ダメージを半減。発動後は1秒の硬直がある。ATB不足でも予約でき、充填まで待つ。マウス用・パッド用の技表示、予約時刻の見積もり、AIの予約、ヘッドレス実行が同じ技定義を参照する。

手動モードでは選択中の仲間が「指示待ち」になる。ATBは充填するが、予約が空でも自分から技を使わない。実行中の技は最後まで続き、予約した技・移動・武器変更も通常どおり実行する。交代は1 ATB・0.6秒の行動として、容量を超えて先頭へ積む。現在の行動とATB充填を待ち、交代開始時にその仲間の後続予約を解除する。交代後は毎回0.8実秒の無料スローを付ける。選択された仲間の実行中の技を中断したり、ATBを返したりはしない。

`State.controlMode` と `control` コマンドで操作モードを記録する。画面の選択だけを理由に、AI鑑賞やヘッドレスの仲間が待機しないよう、AI実行時は全員の自動行動を有効にする。

## 戦場で対象を選ぶ

技を選ぶと、対象を選ぶ場所が横向きの戦場になる。

- 単体技は駒、列技は前列・後列を選ぶ。回復は味方を選ぶ。防御は自分へ直接予約する。
- 選択先の輪郭・列を強調し、行動元から選択先へ線を引く。候補外の駒は薄くする。
- 戦場上部に技名・ATBコスト・対象名・決定／戻るを表示する。
- 駒・列をクリックするか、方向キーで移動し決定する。キーボード・パッドとも対象を保持し、決定を押すたびに末尾へ追加する。
- 予約は合計コストが最大ATBまで（既定4 ATB）。0 ATBの行動を含む手数も最大ATBと同じ。満杯・対象死亡・武器変更後の使用不能を、従来と同じコマンド検証で扱う。

PCの下段とパッド用コンソールにあった対象一覧は、戦場へ移した。コマンド画面では←で前後移動、→で武器切替、↓で防御を直接積む。変更先の役割と機能をボタンへ表示する。○／Bは戻る専用。□／X／Switch Yは対象選択中も一押しで後続取消。薬は↑の道具へ移した。R3で予約一覧。追加・取消だけで予約を扱う。交代補償とFF13の確認内容は[行動入力と交代](command-flow.md)を参照。

## AI鑑賞

右上の「AI鑑賞」で切り替える。開始前にAI方針・予約方式を選んで開始するか、戦闘中に操作を任せる。

| 項目     | 選択肢                                                                               |
| -------- | ------------------------------------------------------------------------------------ |
| AI方針   | 自動行動任せ、攻撃優先、均衡型、後列維持、予告対応、時間操作併用、編成適応、攻勢特化 |
| 予約方式 | 従来AI・1手、予約AI・1手、予約AI・3手                                                |
| 装備方針 | 従来交換、持ち込み維持、対応重視、攻勢特化                                           |
| 再生速度 | 1・2・4倍                                                                            |
| 鑑賞停止 | 停止／再開ボタン、Space。画面を見たまま両方の時計を停止                              |

3人のHP・ATB・実行中の行動・予約と、直近の判断理由・発行した指示を表示する。既定は編成適応・予約3手・対応重視の装備方針。第一戦後は1.2秒の間を置き、選んだ装備方針に従ってヘッドレスと同じ武器更新を行って第二戦へ進む。従来交換ではアルトの2本目を槌、リネの2本目を流星の弓へ交換する。武器は重複使用しない。詳しくは[編成と装備AI](composition-ai.md)。

方針・予約方式の切り替えではAIの判断記憶と未実行の予約をリセットする。実行中の技は続行する。「手動に戻る」でもAIの未実行予約を取り消し、通常速度で手動操作へ戻る。AIへ渡すときは人間が積んだ予約を維持し、時間操作を通常へ戻す。Pの休憩と、別タブへの移動は画面を覆う従来の休憩を使う。

`WatchPlayer` はNode専用の実行器をブラウザへ持ち込まず、既存の `createPolicy` / `createQueuePolicy` と `observe` を使う。判断は15 tick（0.25実時間秒）ごと、反応待ちは既存の0.35秒。画面のフレーム周期ではなくシミュレーションのtickに合わせて入力を発行する。倍速でも刻み・判断頻度・反応時間は変えず、同じ経路で入力を記録する。

## 初回実装時の検証記録（旧版）

- 単体107件：防御のATB待ち・開始時消費、選択中の3人それぞれの待機、選択切替時の実行継続、AI鑑賞の停止・手動復帰など。
- 3つの予約方式で、Web用の4倍速再生とヘッドレス実行が2連戦の最終状態まで完全一致。録画した入力からの再生も完全一致。
- Chrome E2E：マウス・3系統の仮想パッドでの戦場内選択、AI方針・予約方式・速度・停止・手動復帰、戦利品更新と2連戦完走、PC・携帯幅を確認する。
- 画面記録：`test-results/field-target-row.png`、`native-PS-target.png`、`field-target-mobile.png`、`ai-viewing.png`、`ai-viewing-mobile.png`。

現行では `orchestra-6` 以前の保存状態・リプレイは読み込まない。既存のAI攻略限界・予約比較のJSONは防御0 ATBだった旧ルールの実測記録として保持し、現行ルールの結果とは区別する。新規測定の集計は `tempo-study-results.json` に保存した。

敵の独立した状態カードは廃止し、広い陣形の駒にHP・チェイン・ブレイク残時間・行動予告を表示する。編成は武器カードと隊列図で編集し、名称は役割と位置から自動更新する。守護騎士だけをDへ移し、既存の技・数値・前後列の規則を保つ。

## キーボードとパッドの共通化

戦場、仲間選択、コマンド、集中力、予約の配置を共通化。キーボードは基本技Z・主力X・後続取消B・戻るEscの2×2配置、パッドは4ボタンの物理配置を使う。Cで防御、Rで移動、Wで武器変更、Tで予約一覧、Lでログ、Vで薬、Pで休憩。技の対象選択を保持するため、同じ対象にはEnterを繰り返すだけで積める。Escでコマンドへ戻る。↑からオプティマ・一括隊列・道具を開き、既存のA/S/D/G・7/8/9の直接指示も使える。
