# 戻ると後続取消の分離

> 現行の操作は[二重対象・直接操作・アイコン表示](dual-target-controls.md)を参照してください。以下は `orchestra-9` の改修記録です。現在はLTで確定分の後続取消、R3でスロー、Tで補助メニューを開き、下書きは後続取消で消しません。

以下の保留操作・薬ボタン・入力手順は、それぞれの改修時点の記録。

2026-09-07。戦闘ルールは `orchestra-9` のまま、入力と画面状態を変更した。添付案の「戻るを何度押しても予約を変えない」「後続取消は対象選択中も一押し」を採用する。

基本技・主力技、肩ボタンの交代、トリガーの時間操作、R3の予約一覧、L3の印は継続する。戻るは休憩を開始しない。休憩からEsc／戻るで戦場へ戻る操作は継続する。

後続取消は対象・隊列・武器・指示・道具・予約・ログの各画面から直接効く。既存の全予約取消コマンドを利用し、現在の発動・終了硬直・支払い済みATB・未使用ATB・保留設定は変えない。予約が空ならコマンドを発行せず、繰り返しても追加効果はない。一括隊列・オプティマの独立した指示は予約列とは別のため対象外。詳細な実行時間は[ATBと連続行動](atb-sequences.md)を参照。

## 一件取消の着地点

一覧を開くと末尾から選択する。選択を予約ID・キャラ・位置・名称で保持し、取り消した位置には無効な「取消済み」行を残す。決定を繰り返しても次の予約は消えない。方向入力、または別の行の明示的なクリックで再び選ぶ。マウスのダブルクリックも同じ位置の取消済み行に当たる。

選択した予約が先に実行された場合は「実行・取消済み」と表示し、現在の先頭・末尾へ対象を置き換えない。武器予約を取り消した場合の依存技の解除は、既存の戦闘ルールを使う。画面を閉じて一覧へ入り直すと、その時点の末尾を新たに選択する。

押下の立ち上がり検出とキーボードのリピート抑制は継続する。打ち切りの長押し待ち、二度押し、戻った後の待ち時間は設けない。

## 保存と検証

パッド設定は `orchestra-gamepad-v4` へ移行する。v3の `cancel` を `back`、`item` を `cutQueue` に変え、ユーザーが設定した物理番号と軸は保持する。v1・v2も移行する。一つの物理ボタンから二操作を発行しないよう、保存設定の重複割当を検証する。

プレイテストの印には取消済みの選択も保存し、復帰直後の決定で別の予約を消さない。戦闘コアと数値定義に変更はなく、VERSIONは変更していない。新入力で生成したコマンドの再生と保存Stateの一致を確認する。

検証コマンドは `npm test`、`npm run build`、`npm run test:e2e`、`git diff --check`。単体テストでは各画面からの戻る10回・後続取消10回、実行直前の選択消失、取消済み選択の保存復帰を確認する。Chromeでは3系統の仮想パッド、キーボード、マウスのダブルクリック、薬のメニュー、1366×752・1440×900・390×844の表示を検証する。ボタンの押しやすさは今回の実機パッドでは未確認。

検証結果：単体210件、Chrome全50ケースを通過（全体実行48件成功後、通知文言・ヘルプの修正箇所を再実行）。ビルドと差分の空白検査も成功。アプリ内ブラウザで取消済み行を目視し、Chromeの短いデスクトップ幅でボタンと戦場・予約・ログの配置を確認した。
