# 常設操作盤

2026-09-08。コマンド・補助・予約を同時に表示し、次の操作へ進むための「戻る」を不要にするUI変更。戦闘ルールは`orchestra-16`のまま。対象とブレイクの基礎仕様は[二重対象・直接操作・ブレイク表示](dual-target-controls.md)、履歴は[戦闘タイムライン](battle-timeline.md)を参照。

## 画面と操作先

コマンド、補助操作盤、予約欄は常に表示する。補助操作盤には「補助・オプティマ・隊列・ログ」の4つの表示がある。表示を切り替えても技ボタンや予約欄は消えない。ログを読みながら次の下書きを作り、予約をその場で取り消せる。

方向入力の操作先は「対象・補助・予約」の3つ。画面上のボタンで直接選べるほか、キーボード`I` / `T`、パッドのView / Share / −で、対象 → 補助 → 予約 → 対象の順に循環する。補助の表示はこの循環中も保持する。補助へ再入場した際の項目選択は、その表示の初期位置から始める。

| 操作先           | 方向入力                            | 決定                             |
| ---------------- | ----------------------------------- | -------------------------------- |
| 対象             | 駒の位置に沿って選択                | 基本技を下書きへ追加             |
| 補助             | 左右で4表示を切替、上下で項目を選択 | 選択中の指示・薬を実行または追加 |
| ログ表示中の補助 | 左右で表示を切替、上下で履歴を移動  | 最新の記録を表示                 |
| 予約             | 取消対象を選択                      | 選択した未実行の1件を取消        |

「補助」の前後移動からは後列・前列を明示して選べる。どの補助表示からも4つの表示ボタンへ直接移れる。通常の操作盤に戻るボタンは置かない。互換の戻る入力は対象操作へ移すだけで、下書きや確定列を取り消さない。

## 技と薬の追加

戦闘中は`Z`基本技、`X`主力技、`C`防御、`V`救急薬を、現在の操作先にかかわらず下書きへ追加できる。マウス・タッチでは常設の技・薬ボタンを押す。パッドの主力技・防御も全操作先で使える。パッドの基本技ボタンは補助・予約で決定を兼ねるため、対象操作中に基本技を追加する。

救急薬は保持している支援対象へ直接追加する。先に戦場の味方を選べば、その相手が薬や支援技の宛先になる。敵側を編集中でも支援対象を使い、薬を押してから対象選択画面へ入る手順は不要。薬は既存どおり0 ATB・1手で、予約した薬を含めてパーティーの残数を超える追加はできない。

`H` / 右トリガーは表示中の下書きの一組だけを確定する。補助で薬などを選択していても、それを勝手に追加しない。技の追加・行動開始・直接の移動や武器変更を行っても、表示中の補助とその選択位置を保つ。容量不足などで追加できない場合も表示を閉じず、理由を通知する。

攻撃対象と支援対象の保持、自分を対象にする防御、不在対象から生存者への自動切替は既存仕様を維持する。技ボタンと予約欄に対象の小肖像は置かない。宛先は戦場の印、title、読み上げ名で確認する。技追加済みの宛先は、後から保持対象を選び直しても変わらない。

## 一件取消とフォーカス

予約欄の下書き・未実行の確定行は、それぞれ取消ボタンである。押した行を取り消しても、補助やログの表示と操作先を変えない。実行中の一手を取り消す操作ではない。`B` / 左トリガーの後続取消も従来どおり、現在の一手・硬直・下書きを残す。

取り消した行は同じ識別キー、同じネイティブbuttonのまま「取消済み」に変わる。`disabled`でフォーカスから外さず、`aria-disabled="true"`と無処理のクリックで再実行を止める。決定連打・ダブルクリックで隣の行を消さない。次の取消は、Tab、予約操作中の方向入力、または別の行を押して明示的に選ぶ。自動実行で選択行が不在になった場合も、別の予約を自動で取消対象にしない。

## キーボードとパッド

画面上のボタンはTab / Shift+Tabで移動し、Enter / Spaceで決定できる。フォーカスを置くだけでは技の追加、予約の取消、対象変更をしない。ネイティブbutton上のEnter / Spaceは、そのボタンの操作を優先する。戦闘の方向入力による選択位置と、ブラウザーのフォーカスは独立している。

ログには「古い記録・新しい記録・最新」のボタンを置く。これらは対象操作を選んだままでもTabとEnterで使える。ログ本文もフォーカス可能で、本文内の矢印、PageUp/Down、Home/End、Spaceは通常のスクロールとして扱う。ログ本文上のEnterが基本技や予約取消へ流れないようにする。読み上げは`role="log"`、`aria-live="off"`とし、戦闘ログを常時自動で読み続けない。

「十字キーで選択」配置では、Viewなどの操作先切替、十字キー、決定を順に押して対象・補助・予約へ到達できる。薬、移動、武器、一括隊列、対象の敵味方切替を補助から選べるため、アナログ軸や同時押しを必須にしない。標準配置と既存の再割当を保ち、設定の版は`orchestra-gamepad-v7`のまま。

操作先切替と決定が同じ入力ポーリングに入った場合は、操作先を変え、決定側の押下を消費する。たとえば予約を選んでいるときにView+Aを同時に押しても、直前の予約を取り消さない。押し続けた決定を次のフレームへ持ち越さず、離してからの押し直しを必要とする。技・防御・行動開始も同じ競合判定に従う。

休憩や操作説明などのダイアログには、閉じるボタンとEsc / パッドのB・○を残す。フォーカスをダイアログ内に保ち、閉じた後は使用可能な呼出元へ戻す。休憩と操作説明のキーボード経路はE2Eの対象とする。補助やログだけでは戦闘を停止しない。休憩・切断時の停止、動きを減らす設定、色以外の対象形状とフォーカス枠も維持する。

## 状態と保存

`BattlePad.page`は方向入力の操作先、追加した任意の`BattlePad.panel`は表示中の補助を表す。コマンドや予約の操作へ移っても、最後の補助表示を描ける。`visiblePanel()`は`panel`のない旧UI状態では既存の`page`から表示を補い、補助に該当しない場合は通常の補助を使う。

途中の印に含む`PlayView`の検証スキーマにも`panel`を任意項目として追加した。既存の保存を必須フィールド不足で拒否せず、新しい記録では補助表示を復元できる。タイムラインも同じUI状態を場面とともに保持する。過去の明示対象選択状態は互換経路として残す。

変更範囲はReactの操作盤、入力の振り分け、パッドの競合判定、UI保存の形式である。コアへ渡す`draft`・`executeSequence`・`removePlan`などの指示と、戦闘計算・乱数・処理順・各所要時間は変えていない。従って`VERSION`は`orchestra-16`を維持する。交代後も予約を保持するルールと発動0.3秒は前の変更で導入済み。本変更に伴うバランス調整やAI比較の再計測は行わない。
